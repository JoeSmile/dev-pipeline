## 官方 Temporal

票面里的「拉起本地 Temporal」被 2026-11-11 / 2026-11-12 的现行规则覆盖：本仓库 Worker 与现场 History 测试必须连接已经在跑的官方 `agent-platform` Temporal，地址 `127.0.0.1:7233`，容器名 `agent-platform-temporal-1`，官方仓库 `D:\projects\kpl agents\agent-platform`，启动脚本 `scripts/agent_platform_start.ps1`，compose 项目名 `agent-platform`。测试容器内使用 `TEMPORAL_TARGET=host.docker.internal:7233`。

禁止在本仓库再起一份 Temporal，也不要把 `test-docker.ps1 -WithTemporal` 或 `docker compose --profile temporal` 当作默认启动方式。若 7233 没有服务，启动官方栈；不要使用 `temporal server start-dev`。`compose.yaml` 里的 `temporal` profile 若仍存在，不得作为本机默认路径文档化。

「本期不要求对接 agent-platform」只表示不依赖其 worker / app / init 健康，也不在本仓库修复其 schema / init 失败（例如 `phase1-clean-20261103`）。使用其 Temporal 服务作为官方本地 Temporal 已经是现行规则。

## 文档与脚本

- 文档必须 Windows 优先、可复制：Python 3.12 期望、官方 Temporal、本仓库 Worker、`--config-root` 必填、以及 `docker compose run --build --rm test`。
- 宿主机 `python` 经常只是 Windows 商店占位程序，不能用来跑测试。状态机桩测试的受支持路径是 Docker（必须 `--build`），不要求宿主机非 Store Python。
- 克隆请用 SSH。HTTPS 经常失败。
- `scripts/start-worker.ps1` 默认指向 `127.0.0.1:7233`，必填 `-ConfigRoot`，不会启动 Temporal。找不到真实 Python 3.12 时拒绝商店占位并提示文档。
- `scripts/test-docker.ps1` 默认跑桩测试；`-LiveHistory` 打在官方 Temporal；`-WithTemporal` 被拒绝。
- 默认不对外部或远端仓库开放写权限；未确认 L0 前不默认向目标 Story 远程仓库 push 或开 PR。不要把 `D:\projects\dev-pipeline` 当成目标 Story worktree。
