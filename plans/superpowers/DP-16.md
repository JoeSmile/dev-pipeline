# DP-16 决策记录

本记录固化 [DP-16](https://weiperfect007.atlassian.net/browse/DP-16) 人工 `lock_scope` 锁定「要解决 / 不做什么」的主流做法。不扩展范围：不在本票拍技术方案，不离开 `ScopeLocked` 进入方案 / 编码，不派 Coding Child。

## 锁定写入执行记录

合法的 `lock_scope` 把范围从 `Intake` 推到 `ScopeLocked`，并把锁定结果写入现有父执行 Query `snapshot.scope`，不另开第二套 Query。记录至少包含：

- `in_scope`（要解决）
- `out_of_scope`（不做什么）
- `locked_by`（锁定人）
- `locked_at`（时间，UTC ISO-8601，后缀 `Z`）

Signal 沿用已有 `ScopeLock` 字段名，不另造一套 schema。payload 必填为非空的 `in_scope`、`out_of_scope`、`locked_by`。缺必填或类型错误时拒绝，记入 `last_rejection`，阶段保持 `Intake`，不写入锁定记录。`locked_at` 由工作流用确定性的 `workflow.now()` 打戳，忽略客户端传入的时间，避免伪造。

草稿里标 `待证` 的缺项不阻止人工锁定：人的 `lock_scope` 才是决定。本票不臆造验收或约束；payload 未提供这些字段时不填写。本票也不做草稿与锁定内容的冲突计算。

发出 `lock_scope` 之前，编码路径和 Child 派发不可达。锁定成功后本票仍停在 `ScopeLocked` 等待 `decide_scheme`，不得进入 `Implementing`，也不得派 Coding Child。

## reopen 只读继承

`reopen` 仍只在 `Blocked` / `Done` 启动全新父执行。若旧执行已有完整锁定记录，新执行通过 `StoryInput.inherited_scope` 只读继承原文（含原锁定人与原时间，不重新打戳），规范化 Story 草稿后直接进入 `ScopeLocked`，不再等待一次新的 `lock_scope`。再次 `lock_scope` 会被拒绝，已锁范围不得改写。旧执行若在 Intake 尚未锁定就中止，新执行仍从 Intake 等待人工锁定。

## 验收与测试

单元与 WorkflowEnvironment 测试证明：未锁前 Child 不可达；合法锁定写入四字段并进入 `ScopeLocked`；缺必填被拒绝且阶段不变；Query 可读已锁范围；reopen 只读继承完整记录。现场 History 打在已运行的官方 Temporal（`TEMPORAL_TARGET`，例如 `host.docker.internal:7233`），覆盖合法锁定与缺字段拒绝，不起临时 Temporal 服务。
