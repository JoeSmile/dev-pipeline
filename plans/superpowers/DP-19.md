# DP-19 决策记录

本记录固化 [DP-19](https://weiperfect007.atlassian.net/browse/DP-19) 在 `TicketsReady` 产出拆票清单、以「清单齐」作为进入 `Implementing` 与派 Child 的门禁，以及把票幂等写入 Jira 项目 `DP` 的主流做法。不扩展范围：不在本票实现写码 Worker / Cursor CLI 写码循环，不维护仓库 `TASKS.md`，不引入「可延后」类型，不开始 [DP-20](https://weiperfect007.atlassian.net/browse/DP-20)。编排仍复用 [DP-26](https://weiperfect007.atlassian.net/browse/DP-26) 与既有父 / Child 骨架，不另做第二套编排器。

## 清单如何产生

父执行到达 `TicketsReady` 之后（无红线级假设跳过 Spike，或 Spike 过线），清单来自已记录的结构化输入，不由模型临场编造，不读取 `CURSOR_API_KEY`，不调用 Cursor CLI：

1. 启动 payload 或 `decide_scheme.tickets` 里若已有完整清单，直接采用。
2. 否则停在 `TicketsReady`，`waiting_signal=submit_tickets`，等候人工 Signal `submit_tickets`。非法或未齐的 payload 拒绝，记入 `last_rejection`，阶段不变。
3. 每张必做 Ticket 必须同时具备非空且不是「待证」的 `ticket_id`、目标、验收、I/O 契约，以及依赖列表（无依赖则为空列表）。缺项、重复 `ticket_id`、未知依赖或成环，均视为清单未齐。本期全部清单项都是必做。

清单与完整标记挂在既有父执行 Query（`snapshot.tickets` / `snapshot.ticket_list_complete`），不另开第二套 Query。

## 清单齐门禁

`StoryInput.auto_start_children` 不再是派 Child 的充分条件。空清单或不完整清单即使该开关为 True，也不得进入 `Implementing`，不得派 Coding Child / Coding Worker。生产与 CLI 默认仍是空清单，因此会停在 `TicketsReady` 等候 `submit_tickets`。清单齐之后，父执行才进入 `Implementing`，并为每张必做 Ticket 建立对应 Child。既有骨架测试改为提供完整清单，而不再依赖不完整清单上的过渡开关。

## Child 与依赖

复用既有 `TicketWorkflow` 与拓扑函数，不另做编排器。清单齐后一次为每张必做 Ticket 建立 Child（幂等键仍是 `ticket_id + execution_id`，见 [DP-11](https://weiperfect007.atlassian.net/browse/DP-11)）。无未完成依赖的 Child 可并行进入 `Implementing`；依赖未满足的 Child 保持 `Pending`，不得进入 `Implementing`。快照上 `child_created` 表示 Child 已建立，`started` 仍表示已获准开始工作。

## Jira 写入

票落在 Jira 项目 `DP`，由 Activity `persist_jira_tickets` 经既有 `jira.toml` / `JiraHttpStore` 写入。项目键固定为 `DP`；工单类型约定为 `Story`（若以后要改类型，标待证，不发明自定义字段名；`stage_field` 仍按 [DP-14](https://weiperfect007.atlassian.net/browse/DP-14) 为待证）。幂等键写在描述里的 `dp-ticket:{story_id}:{ticket_id}:{execution_id}`：重试先查找再创建，不重复建票。失败像阶段镜像一样记为可见滞后（`snapshot.jira_tickets`），不吞掉，也不因此回退父阶段。重试策略与既有 Jira Activity 一致。单元与 live 测试一律走 InMemory / Stub 假 Jira，不向 weiperfect007 的真实 `DP` 项目写票。不写 `TASKS.md`。

## reopen

`reopen` 仍不继承方案或 Spike。新执行若只带启动 payload 里的票，是否以及如何只读继承已提交的完整清单 / Jira key / Child，标 `待证`，本票不静默发明继承规则。

## 验收与测试

单元与 WorkflowEnvironment 测试证明：完整清单项含目标、验收、依赖、I/O 契约，并对应一个 Child 与一次假 Jira 写入；清单未齐时不进 Implementing、不派 Child；清单齐后父执行进入 Implementing 且每张必做票都有 Child；依赖未满足的 Child 不进入 Implementing，无依赖的可并行；不写 `TASKS.md`；Jira 写入重试幂等，失败可见；`auto_start_children=True` 加空或不完整清单不再派 Child。现场 History 打在已运行的官方 Temporal（`TEMPORAL_TARGET`，例如 `host.docker.internal:7233`），覆盖清单齐后建立 Child、清单未齐不派 Child、依赖未满足不得进入 Implementing，不起临时 Temporal 服务，不写真实 Jira 票。
