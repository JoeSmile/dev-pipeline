# DP-13 决策记录

本记录固化 [DP-13](https://weiperfect007.atlassian.net/browse/DP-13) 用 CLI 启动进入 Intake 的主流做法。不扩展范围：不实现 Jira 标签自动开跑（见 [DP-39](https://weiperfect007.atlassian.net/browse/DP-39)），不实现 Signal / 状态查询 CLI（见 [DP-28](https://weiperfect007.atlassian.net/browse/DP-28)），不实现完整 Intake 契约票（见 [DP-37](https://weiperfect007.atlassian.net/browse/DP-37)），也不把 Jira 当成编排器，不接 MCP，不做产品 UI。

## 启动入口

本仓库提供控制台脚本 `dev-pipeline`，当前只实现子命令 `start`，便于 [DP-28](https://weiperfect007.atlassian.net/browse/DP-28) 以后扩展 `status` / `signal`。等价入口为 `python -m dev_pipeline.cli`。

可复制的验收命令：

```powershell
dev-pipeline start --jira-key DP-13 --config-root D:\pipeline-config
```

可选参数：`--execution-id`（省略则生成 UUID 并打印）、`--temporal-target`（默认 `localhost:7233`）、`--task-queue`（默认 `dev-pipeline`）。

输入是 DP 项目的 Jira key（形状为 `DP-` 加数字）。CLI 只校验 key 形态，不把 Jira 当编排器，本票也不拉取远端 Issue 正文。

## 共享 Intake 形状（给后续 DP-37 / DP-39 预留）

引入轻量、可序列化的 `IntakeRecord`：`jira_key`、`提出人`（`reporter`）、`原始诉求`（`request`）、`来源`（`source`）、是否带自动开跑标签（`has_auto_run_label`）。缺失字段一律标为 `待证`。CLI 路径填写 `source=cli`，其余未提供字段为 `待证`。后续标签监听路径必须填入同一形状（例如 `source` 另取值），不得另起一套 Intake。

`StoryInput` 增加可选字段 `intake`。CLI 用 `story_input_from_intake` 组装启动载荷：`story_id` 等于 Jira key，Ticket 清单为空（Intake 尚未拆票），`summary` 取原始诉求（CLI 下为 `待证`）。父执行 id 仍是既有的 `story_workflow_id(story_id, execution_id)`。查询快照带上 `intake`，便于对上 Intake，但不实现 DP-28 的查询 CLI。

## 配置与失败可见

启动是 Activity-free 的 Temporal Client 调用，I/O 留在 CLI 进程，不进 Workflow。连接使用既有的显式 `CLIENT_CONNECT_TIMEOUT`，`start_workflow` 带显式 `rpc_timeout`，并设置 `WorkflowIDReusePolicy.REJECT_DUPLICATE` 与 `WorkflowIDConflictPolicy.FAIL`。

启动前先校验：

- `--config-root` 必填且必须是已存在的绝对目录，沿用 [DP-29](https://weiperfect007.atlassian.net/browse/DP-29) 的 `validate_config_root_path`。
- 配置根目录必须能装入合法 `budget.toml`（与 [DP-12](https://weiperfect007.atlassian.net/browse/DP-12) Worker 启动校验一致）。本票启动虽不读其他密钥，缺必填配置仍立即失败。

缺失或非法配置以中文错误立即失败并非零退出，不连接 Temporal，也不回退默认路径或隐藏限额。

启动失败必须可见并中止，**不得**吞掉后说「可能已存在」或把接入已有执行当成成功。这是 agent-platform 的硬教训：配置根缺失导致的启动失败曾被当成可能已存在，后续发送会挂死。下列情况一律非零退出并输出中文原因：

- Jira key 非法或缺失
- 配置根目录或 `budget.toml` 缺失 / 非法
- Temporal 不可达
- 启动载荷非法
- 目标 `workflow_id` 已存在（明确报告失败，不 attach、不假装成功）
- 其他 `start_workflow` 异常

成功时在标准输出打印 `workflow_id`、`execution_id` 和 Jira key，并写明已进入 Intake。运维日志走 structlog。

## 验收与测试

给定 DP 项目的 Jira key，CLI 启动对应父执行；在 `WorkflowEnvironment` 下查询快照为 `Intake`，History 中的启动事件能对上这次 start（workflow id 与 Intake 载荷）。本票不依赖本机 Docker 或已启动的 Temporal 服务。
