# DP-24 决策记录

本记录固化 [DP-24](https://weiperfect007.atlassian.net/browse/DP-24) Verifying 门禁与「红线 ↔ 证据」的主流做法。证据落盘格式遵守 [DP-32](https://weiperfect007.atlassian.net/browse/DP-32) 的最小字段与 UTF-8 约定，不另发明第二套格式。本票不把 DP-32 标为完成，不实现 Retro，不把 Joe 当测试员，也不改 HumanGate / `TestDeploying` 名称。

## 门禁

Ticket Child 进入 `Verifying`（仅建议 / 信息直达，或 HumanGate 放行）后，必须在该 Ticket 的授权 worktree 内跑可复现检查，并写出至少一行「红线 ↔ 证据」。过线进入既有阶段 `Verified`。未守住红线时，只让该 Ticket Child 回到 `Implementing`，重新进入写码 / 交付物路径；不自动取消或回退同胞 Ticket，父执行保持聚合 `Implementing`，不得因此进入 `Retro`。

dry-run 或仅观察到 Temporal History 存在，一律不能标 PASS。两种路径仍会按同一契约写证据（若路径落在授权树内）。

## 红线来源与证据

红线复用已冻结的 L0 / CHARTER（至少：可复现证据、授权 worktree、单文件 2000 行）、worktree 内 `STORY_CONSTRAINTS.md` 的本 Story 局部约束，以及父执行传入的方案红线级假设。未知项标 `待证`，不臆造。确定性后端在授权树内执行真实命令或可观察现象，不调用现场 Cursor CLI，不读取 `CURSOR_API_KEY`。预留的 CLI 适配器保持未接线。

证据文件默认写在授权 worktree 的 `evidence/verify.md`，编码 UTF-8。过线与失败都写。最小字段：`对应红线`、`命令或现象`、`结果`、`证据路径`，以及 `ticket_id` / `execution_id`。记录挂在既有快照字段 `snapshot.verify` / `tickets[].verify`，不另开第二套 Query。越界写入按既有沙箱拒绝方式记录，文件不得落到授权树外。

## 既有门禁

不回退 DP-23 `review_override`、仅建议 / 信息跳过 HumanGate、DP-22 双审查与 2000 行硬闸门、审查只读、`_start_eligible` / `ticket_event` 依赖唤醒，以及 DP-21 交付物、DP-20 沙箱、DP-11 幂等、DP-16 / DP-17 / DP-18 / DP-19 门禁。父 / Child Workflow 不含 LLM / CLI / 文件系统写入。`reopen` 对验证记录的继承仍为待证。

## 验收与测试

单元与 WorkflowEnvironment 测试证明：过线写出 UTF-8 最小字段证据、对得上红线、Child 进入 Verified，且快照与 History（`verify_ticket` Activity）可见；失败也写证据，只打回该 Ticket 到 Implementing，同胞不被取消，父执行不进 Retro；dry-run 或仅 History 不能标 PASS；验证在授权 worktree 内跑，越界证据写入被拒。现场 History 打在已运行的官方 Temporal（`TEMPORAL_TARGET`，例如 `host.docker.internal:7233`），覆盖过线与失败打回；使用临时授权树和假 Jira，不起临时 Temporal 服务，不写真实 Jira 票，不调用现场 Cursor CLI。失败打回后等候下一次 implement，并在拆除时释放 hold；不 terminate 已完成的 Workflow。
