# DP-25 决策记录

本记录固化 [DP-25](https://weiperfect007.atlassian.net/browse/DP-25) Story Retro（日记与 candidate）以及禁止静默升级的主流做法。本票不产品化 `TestDeploying`（名称与既有骨架路径保持：`Implementing → authorize_test_deploy → TestDeploying → Retro → Done`），不改 Codex 原有环境复盘 Skill，也不把 Story Retro 写成个人日终复盘或「技术难度 / 业务难度」打分日报。

## 门禁

全部未移除的必做 Ticket 验证过线后，父执行仍停在聚合 `Implementing`，等候既有人工 Signal `authorize_test_deploy`。授权后走已锁定名称的 `TestDeploying` 桩；只有测试部署成功才允许进入 `Retro`。测试部署失败、仍有未验证或未处理失败的必做 Ticket、或验证失败打回 Implementing 时，不得进入 `Retro` 或 `Done`。被 `drop_ticket` 移除的 Ticket 不再阻挡。

进入 `Retro` 后，确定性 Activity `write_retro_record` 把本 Story 证据追加进当天 daily，并更新 candidate。写入成功后父执行进入 `Done`。写入失败不得进入 `Done`，转入 `Blocked`（`retro_write_failure`）。

## 日记与 candidate

日记默认路径是知识根目录下的 `docs/knowledge/daily/YYYY-MM-DD.md`。日期由 Workflow 用确定性的 `workflow.now()` 换算为 Asia/Shanghai 日历日，再传给 Activity；不读取操作系统本地时区，也不在 Workflow 里调用 `datetime.now()`。知识根目录来自可选的 `workspace.toml`：优先 `knowledge_root`，否则 `authorized_root`，再否则 `config_root`。不把流水线仓库本身当成目标 Story 的工作树或默认知识根。

若当天文件已存在，只追加本 Story 段落，不覆盖同日其他 Story 的内容。编码 UTF-8。每条陈述必须能引用证据源；无引用则标 `待证` 或删除。禁止写成技术难度 / 业务难度打分。Story Retro 不替代日终复盘 Skill。

candidate 写在 `docs/knowledge/candidates/`。Retro 可以根据本 Story 证据记录或累加真实命中、硬近失（例如验证守住的红线、方案中的「候选」假设、经 HumanGate 后仍过线的近失）。默认可晋升条件：真实命中 N≥2，或一次硬近失。这些数字条件可在确认 L0 时再改拍，本票不静默修改。Retro 本身禁止把 candidate 升为 L0 或全局 Skill。

结果挂在既有查询快照的 `snapshot.retro`，不另开第二套 Query。History 中可见 `write_retro_record` Activity。

## promote_rule

候选升 L0 / 全局 Skill 必须人工 Signal `promote_rule`。payload 必填：候选标识、晋升目标（`L0` / `全局 Skill`）、理由、证据引用（也接受中文别名）。调用方传入的时间一律忽略，由 Workflow 用 `workflow.now()` 落时间。合法晋升写入对应 candidate 文件，并记入 `snapshot.promotion` 与 `promote_rule_status`；History 中可见 `apply_promote_rule`。

`automatic=true`：Signal 已接收，但晋升动作被拒绝并记录（禁止静默升级）。这不是忽略 Signal。缺字段、未知候选、错误目标、缺少证据引用、未达默认晋升条件：记入 `last_rejection`，不晋升。未发现已签署的 L0 覆盖配置，因此不能跳过 N≥2 / 硬近失门槛。

## 既有门禁

不回退 DP-24 Verifying（过线证据、失败只打回该 Ticket、dry-run / 仅 History 不能标 PASS、`refresh_ticket_wait`），不回退 DP-23 `review_override`、DP-22 双审查与 2000 行硬闸门、`_start_eligible` / `ticket_event`，以及 DP-21 / DP-20 / DP-11 / DP-19 / DP-16 / DP-17 / DP-18。父 / Child Workflow 不含 LLM / CLI / 文件系统写入。`reopen` 对 Retro / 晋升记录的继承仍为待证。不改 Codex 环境复盘 Skill，不产品化 TestDeploying。

## 验收与测试

单元、文件系统与 WorkflowEnvironment 测试证明：全部必做 Ticket 过线且测试部署桩成功后，当天 UTF-8 daily 存在、证据可引用（否则 `待证`）、candidate 已更新但未自动晋升，父执行进 Done，快照与 History 可见；未全部过验证或验证失败时不能进 Retro / Done；自动晋升被拒绝；合法 `promote_rule` 晋升且可见；非法 / 不完整 / 未达条件的 `promote_rule` 被拒绝并记入 `last_rejection`；日记不是难度打分；追加同日文件不覆盖先前内容。现场 History 打在已运行的官方 Temporal（`TEMPORAL_TARGET`，例如 `host.docker.internal:7233`），覆盖 Retro→Done、未验证不得进 Retro、以及 `promote_rule` 路径；使用临时知识树和假 Jira，不起临时 Temporal 服务，不写真实 Jira 票，不调用现场 Cursor CLI。不 terminate 已完成的 Workflow。
