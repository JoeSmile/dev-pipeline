# DP-22 决策记录

本记录固化 [DP-22](https://weiperfect007.atlassian.net/browse/DP-22) 双 Review 并行输出与规则引用的主流做法。不扩展范围：不产品化 HumanGate（见后续票），不实现完整 Cursor CLI 运行时（见 [DP-46](https://weiperfect007.atlassian.net/browse/DP-46)），不把 [DP-44](https://weiperfect007.atlassian.net/browse/DP-44) 的其余规范化产品化；只落实「单文件超过 2000 行必须阻断，不得用建议项放行」这条硬闸门。

## 双审查如何运行

交付物齐备并进入 `Reviewing` 后，Child 并行启动两个 Activity `review_ticket`（`worker_id` 为 `standards` / `spec`），各自只读审查 diff、已冻结的 L0（`docs/CHARTER.md`）与本 Story 局部约束（工作区中的 `STORY_CONSTRAINTS.md`，缺文件则标 `待证`）。结论分为阻断 / 建议 / 信息，并引用仓库中已有的规则条文；引用目标缺失时标 `待证`，不发明新的 L0 文本。

确定性后端实际做分类与门禁，不调用现场 Cursor CLI，不读取 `CURSOR_API_KEY`，不假装模型已跑。规范审查侧重 CHARTER / 范式边界；规格审查侧重本 Story 局部约束。两条都执行 2000 行硬闸门。

并行一轮结束后即停，停止原因复用 [DP-12](https://weiperfect007.atlassian.net/browse/DP-12) 既有的「无新证据」表述，不再追加审查轮次，也不另建第二套预算账本。耗费用的互辩 / RAG / 多模型仍走父执行 `start_costly_path`。

## 分歧规则与快照

聚合结果写入既有 Child / 父快照字段 `review`（`TicketResult` / `TicketSnapshot`），不另开第二套 Query。

- 任一审查给出阻断或判定范式漂移，进入 `HumanGate`，等候既有 `review_override`；本票不实现人工裁决产品，也不得自动放行。
- 两条都阻断且理由冲突时，仍进 `HumanGate`，`auto_arbitrated` 保持为假，Workflow 不做自动仲裁。
- 仅建议或信息时直达 `Verifying`。

范式漂移的可检测定义来自已冻结 CHARTER：静默修改 `CHARTER.md`，或把 LLM / 密钥 / 非确定性调用引入 `src/dev_pipeline/workflows/`。

## 2000 行硬闸门（对齐 DP-44）

引入或膨胀到超过 2000 行的单个文件，必须给出阻断，引用 CHARTER 硬红线第 9 条 / 一期工作默认第 7 条。不得把该结论降为建议。更严软上限未拍前不以软上限冒充已定，本票不写完整风格指南。

## 只读与预留 CLI（对齐 DP-46，不接线）

Review Worker 默认只读 diff。即使路径落在授权 worktree 内，审查写入也走既有路径守卫并以只读策略拒绝，记入快照，工作区保持不变。

`review_cli_adapter.plan_review_cli` 只构建 `agent -p --mode=ask --workspace <授权目录>`，禁止 `--force`、`--resume`、`--continue`、`--worktree` 与 `--api-key`。适配器默认不接线，不启动进程，不读取密钥。预留跑完后须检查工作区无改动；本票不调用现场 CLI，也不实现 stream-json 心跳或三类 Activity 运行时。

## 既有门禁

双审查会增加 Child 向父执行的进度通知次数。父编排在 `_start_eligible` 之后若先清掉 `ticket_event` 再进入等待，可能丢失“依赖已过线”的唤醒，让后续 Ticket 停在 Pending。本票把该清位移到等待之后，既有并行 / 依赖 / 同胞不被取消的测试继续覆盖。

不回退 DP-21 交付物齐才进 Reviewing，也不回退 DP-20 沙箱、DP-11 幂等、DP-16 / DP-17 / DP-18 / DP-19 门禁。HumanGate 本身保持等候人工 Signal。Spike 默认 4 小时与 `reopen` 对方案 / Spike / 清单的继承仍为待证。`models.py` 仅增加快照字段 `review`，审查类型放在 `review.py`，不做大搬家。

## 验收与测试

单元与 WorkflowEnvironment 测试证明：双审查并行跑完，结论带规则引用；阻断或范式漂移进 HumanGate 且不自动放行；冲突阻断不自动仲裁；仅建议 / 信息到 Verifying；超过 2000 行必须阻断且不得降为建议；审查写入被拒且工作区不变；无新证据不开始下一轮审查；预留 CLI 参数符合上述约定。父 / Child Workflow 不含 LLM / CLI / 文件系统写入。现场 History 打在已运行的官方 Temporal（`TEMPORAL_TARGET`，例如 `host.docker.internal:7233`），覆盖阻断进 HumanGate、仅建议到 Verifying，以及可行时的 2000 行阻断；使用临时授权树和假 Jira，不起临时 Temporal 服务，不写真实 Jira 票，不调用现场 Cursor CLI。若 Child 停在 HumanGate，断言后 terminate / abort。
