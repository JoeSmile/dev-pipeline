# DP-21 决策记录

本记录固化 [DP-21](https://weiperfect007.atlassian.net/browse/DP-21) 按 Ticket 交付分支、diff、单测与回滚说明，齐了才进入 Reviewing 的主流做法。不扩展范围：不实现 Review / 双审查（见 [DP-22](https://weiperfect007.atlassian.net/browse/DP-22)），不实现完整 Cursor CLI 运行时（见 [DP-46](https://weiperfect007.atlassian.net/browse/DP-46)），不产品化 PR 授权（见 [DP-31](https://weiperfect007.atlassian.net/browse/DP-31)），不回收 worktree（见 [DP-30](https://weiperfect007.atlassian.net/browse/DP-30)）。

## 交付物如何产生

复用 [DP-11](https://weiperfect007.atlassian.net/browse/DP-11) 的工作区声明与 [DP-20](https://weiperfect007.atlassian.net/browse/DP-20) 的授权 worktree。幂等键仍是 `ticket_id + execution_id`。分支名复用既有 `derive_branch_name`（`ticket/<ticket_id>/<execution_id>`）。

1. Child 在依赖满足并完成工作区声明后，由 Activity `implement_ticket` 调用确定性交付后端，在授权 worktree 内初始化本地 git 仓库（如尚不存在）、检出可推导分支、写入最小实现与单测、写下回滚说明，并在该 worktree 内运行 `unittest`。
2. 后端走 `apply_guarded_write`，不越出授权目录。不调用现场 Cursor CLI，不读取 `CURSOR_API_KEY`，不自建 agent 循环。
3. 默认不 `git push`、不合并、不改全局 Git 规则、不开远程 PR。产物只留在授权 worktree 与本地分支。
4. 同键重入复用已有分支与提交，不新开 PR，不重置或改乱分支。
5. 缺少授权 worktree 时交付未齐，不进入 Reviewing，也不进行远程 push / 合并 / PR。

## 完整性门禁与快照

进入 Reviewing 的硬条件是四项都齐：可推导的本地分支、可审查 diff、单测证据、回滚说明；单测必须在该 Ticket 的授权 worktree 内跑过。缺任何一项则记入既有 Child / 父快照字段 `deliverables`（`TicketResult` / `TicketSnapshot`），阶段进入 `Failed`，不进入 Reviewing，不另开第二套 Query。

## Reviewing 与 HumanGate

本票不实现 Review Worker。交付齐后进入 `Reviewing` 即止于本票范围；既有审查桩与 HumanGate 规则保持不变：仅建议/信息可从 Reviewing 到 Verifying，阻断项或范式漂移必须经 HumanGate，不得把交付完成当成 Review 通过，也不得自动放行 `review_override`。

## 预留 Cursor CLI 适配器（对齐 DP-46，不接线）

`coding_cli_adapter.plan_coding_cli` 只通过既有 `coding_cli.py` 构建 `agent -p --force --trust --workspace <授权目录>`，禁止 `--worktree` 与 `--api-key`。该适配器默认不接线，不启动进程，不读取密钥。缺配置根或 key、以及非 0 退出的处理仍由既有 `coding_cli` 约定保留，本票不调用现场 CLI。

## worktree 回收与 PR 授权

交付时仍只留下 `worktree_recycle` 标记，不在写码当下删除目录。[DP-30](https://weiperfect007.atlassian.net/browse/DP-30) 已在 `abort` 时由 Activity 回收本 execution 创建的未合并 worktree / 本地分支。开远程 PR 的授权条件仍标 `待证`，默认视为未授权；[DP-31](https://weiperfect007.atlassian.net/browse/DP-31) 已把该默认与生产目标拒绝记录写成验收，不产品化授权流程。

## reopen 与既有门禁

不回退 DP-16 / DP-17 / DP-18 / DP-19 门禁。Spike 默认 4 小时仍为待证。`reopen` 仍不继承方案 / Spike / 清单 / Jira key（待证），也不复用已乱掉的工作区。`models.py` 因快照字段略超 600 行软上限，下一步拆分快照类型，本票不借机做大搬家。

## 验收与测试

单元与 WorkflowEnvironment 测试证明：交付齐后快照上有可推导分支、可审查 diff、单测证据和回滚说明，并进入 Reviewing；单测在授权 worktree 内跑；缺项不进 Reviewing；同键重跑不新开 PR、不改乱分支；未授权路径没有远程 push / 合并 / 远程 PR；父 / Child Workflow 不含 LLM / CLI / 文件系统写入；既有越界拒绝与幂等、清单、范围 / 方案 / Spike 门禁不回退。现场 History 打在已运行的官方 Temporal（`TEMPORAL_TARGET`，例如 `host.docker.internal:7233`），覆盖交付齐进入 Reviewing，以及未授权时不远程 push；使用临时授权树和假 Jira，不起临时 Temporal 服务，不写真实 Jira 票，不调用现场 Cursor CLI。若 Failed Child 会等候重试，断言后 terminate / abort。
