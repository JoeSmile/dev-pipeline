## 命令与退出码

三条路径都走本仓库 CLI，失败时以中文原因非零退出，不得把失败说成「可能已存在」或吞掉必填参数。

| 退出码 | 含义 |
| --- | --- |
| 0 | 成功：`start` 已进入 Intake；`signal` 已被 Workflow 接受；`status` / `--follow` 查询成功 |
| 2 | 用法或配置错误：缺必填参数、`--config-root` 缺失或不是已存在的绝对目录、payload 缺字段、未知 Signal、`budget.toml` 非法（仅 `start` 会读预算文件） |
| 1 | 运行失败：Temporal 不可达、找不到父执行、启动冲突、Workflow 拒绝了 Signal（阶段不变） |
| 130 | `status --follow` 被 Ctrl+C 中断 |

Windows 是第一本地环境，可复制命令见 README 与 `docs/dev-setup.md`。

## Signal

`dev-pipeline signal` 只发送工作流里已经定义的人工 Signal：`lock_scope`、`decide_scheme`、`approve_spike`、`submit_tickets`、`review_override`、`promote_rule`、`authorize_test_deploy`、`abort`、`reopen`，以及路由到 Child 的 `retry_ticket` / `drop_ticket`。不另开第二套 Signal 名单。必填字段在 CLI 侧用既有 `parse_human_signal` 校验；缺项在发送前以退出码 2 失败。`ticket_state_changed` 是 Child 回写，不开放给操作 CLI。

发送后 CLI 只读 Query 确认结果：新的 `last_rejection` 且信号名匹配则打印「Signal 已被拒绝，阶段未改变」并以退出码 1 失败；阶段、等候点或其他可观察字段变化则打印新的 `stage` / `waiting_signal` / 「正在等候你确认××」。CLI 不会在超时后自动放行门禁。观察超时沿用客户端连接超时（10 秒），不是新的 SLA。

## status / follow

`dev-pipeline status` 继续调用既有父 Query `snapshot`，打印当前步骤、最近进度行、最近心跳，以及等候确认与「可能无响应」。`--follow` 持续刷新，默认间隔 2 秒（待证占位，与心跳间隔占位相同），直到 Ctrl+C，或满足 `--follow-until waiting|stage-change|expired`，或达到 `--follow-max`。跟随只查询、不改阶段、不写 Jira、不写文件，也不会因显示过期或等候而自动发送 Signal。心跳过期只标「可能无响应」，与 Failed / Blocked / 「正在等候你确认××」可区分。
