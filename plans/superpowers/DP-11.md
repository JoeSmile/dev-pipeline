# DP-11 决策记录

本记录固化 [DP-11](https://weiperfect007.atlassian.net/browse/DP-11) 幂等执行的主流做法。不扩展范围：不实现真实 Coding Worker（[DP-20](https://weiperfect007.atlassian.net/browse/DP-20) / [DP-21](https://weiperfect007.atlassian.net/browse/DP-21)），不处理分支 / worktree / PR 扫尾（见 [DP-30](https://weiperfect007.atlassian.net/browse/DP-30)）。

## 幂等键就是 Child workflow id

键格式为 `ticket_id+execution_id`，由 `ticket_workflow_id` 生成，并作为 `TicketWorkflow` 的 workflow id。父执行 id 仍是 `story_workflow_id(story_id, execution_id)`。`retry_ticket` 是同一次执行内对同一 Child 的重试，不得分配新的 `execution_id`，也不得改键。

## 三种情况

1. **同键、执行仍在进行中**：视为重入。父执行若已持有 handle 或该 Ticket 已 started，则复用，不再 `start_child_workflow`，也不再发送 `dependencies_satisfied`。即使第二次启动被尝试，也只附着到已有 execution，不得产生第二份副作用。
2. **同键、执行已完成**：`id_reuse_policy=REJECT_DUPLICATE` 拒绝用同一 id 再开新 run。第二次启动附着到已有 execution，或通过已有 handle 返回原结果。不得开新分支 / PR / worktree 声明。
3. **不同 `execution_id`（含 `reopen`）**：这是新一次执行、新键。只启动新的 Child id，不得 signal 或继跑旧 Child，也不得复用旧工作区声明。

## Child 启动策略

`start_or_attach_ticket_child` 使用 Temporal `WorkflowIDReusePolicy.REJECT_DUPLICATE`，已完成或仍在运行的同一 id 都不得作为新 run 启动。Child 的 `start_child_workflow` API 没有 `id_conflict_policy`；第二次启动若收到 `WorkflowAlreadyStartedError`，则 `get_external_workflow_handle_for` 附着到已有 execution，父执行不得因此失败，也不得再创建一个 Child。

## 工作区 / 副作用声明

因为真实写码 Worker 不在本票范围，`claim_ticket_workspace` Activity（以及 `implement_ticket` 桩里的可替换 hook）按同一键记录：工作区身份、分支名、PR-like token。这些名字和路径都包含 `execution_id`，不会指向共享的 `main`。同一键的第二次调用返回第一次声明，且 created 计数保持为 1。不同 `execution_id` 得到不同身份。声明写入只发生在本键上，Ticket A 失败不得写入 Ticket B 的槽位。这是进程内桩，不访问 git 或 GitHub。

## 隔离不变量

每张 Ticket 的工作区身份都按 `ticket_id+execution_id` 隔离。单张失败只影响自己的声明。已合并主线不在声明空间里（分支名永远不是 `main`，也不是共享 worktree 路径）。真实 worktree 回收见 DP-30。
