# DP-27 决策记录

本记录固化 [DP-27](https://weiperfect007.atlassian.net/browse/DP-27) 的只读 Query 与等候点可观测性。不另开第二套 Query：阶段、正在等待的 Signal、Ticket 清单与各 Child 状态、已耗预算、最近失败原因、Jira 镜像是否滞后，仍挂在现有父执行 `snapshot` 上。执行过程快照挂在同一快照的 `progress` 字段：当前步骤、最近心跳时间、心跳是否过期、最近有限条步骤提示。细则里的进度契约来自 [DP-47](https://weiperfect007.atlassian.net/browse/DP-47)，但本票不交付 CLI 跟随刷新、MCP、BA 视图，也不接线现场 Cursor `stream-json`。

## Query 与 History

阶段、等候点、预算、失败原因和镜像字段由 Workflow 状态计算，必须与 History 一致。Query 本身不改变阶段，不写 Jira，不写文件。等候点（`lock_scope`、`decide_scheme`、`approve_spike`、`submit_tickets`、`review_override` / HumanGate、`authorize_test_deploy`、`promote_rule` 等）不得超时自动放行。

当前步骤与心跳来自本 execution 证据目录（`knowledge_root/docs/knowledge/executions/<execution_id>/`，知识根沿用已有 `workspace.toml` 约定）下的 UTF-8 `progress.log` / `heartbeat.json`，以及 Temporal Activity heartbeat。它们不必写入 History；完整思考、密钥或完整文件内容不得进入 History、进度日志或对外视图。Query 只返回有限条最近提示，不把整份日志打进 Workflow History。

## 等候、过期与失败的区分

等候人工 Signal 时，快照的 `progress.waiting_confirmation` 为「正在等候你确认××」，不得显示成无响应。心跳过期只标「可能无响应」，且与 Failed、Blocked、等候 Signal 可区分。显示过期本身不会把 Workflow 判失败；真正失败仍以 Activity 失败或 Temporal heartbeat timeout 为准。

心跳间隔（默认 2 秒）与显示过期阈值（默认 10 秒）均为**待证**占位，不是已签署的 SLA。无新步骤时 Activity 仍按该间隔心跳。
