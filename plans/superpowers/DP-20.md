# DP-20 决策记录

本记录固化 [DP-20](https://weiperfect007.atlassian.net/browse/DP-20) 写码沙箱的主流做法：写码 Worker 只能改授权 repo / worktree，越界必须失败并可观测，LLM 不进父 Workflow，Windows 路径必须作为验收环境之一。不扩展范围：不定义交付物清单（见 [DP-21](https://weiperfect007.atlassian.net/browse/DP-21)），不实现完整 Cursor CLI 运行时（见 [DP-46](https://weiperfect007.atlassian.net/browse/DP-46)），不产品化 PR 授权流程（见 [DP-31](https://weiperfect007.atlassian.net/browse/DP-31)），不回收 worktree（见 DP-30）。

## 授权 worktree 如何建立

复用 [DP-11](https://weiperfect007.atlassian.net/browse/DP-11) 的工作区声明，不另做第二套权限系统。幂等键仍是 `ticket_id + execution_id`。

1. 配置根目录可选 `workspace.toml`，字段只有 `authorized_root`，必须是已存在的绝对目录。
2. 缺少该文件时默认未授权，`WorkspaceClaim.authorized_worktree` 为空，沙箱拒绝任何写入。
3. 文件存在但非法时可见失败，不回退到隐藏默认路径。
4. 合法配置下，声明的授权 worktree 为 `<authorized_root>/<ticket_id>/<execution_id>`。同键重入返回第一次路径，不得创建第二份声明；新的 `execution_id` 使用新路径。
5. 声明活动可以在授权根目录内创建该 worktree 目录，但不使用 Cursor CLI 的 `--worktree`，也不自动 `git worktree`。

## 越界如何拒绝并记录

写码路径的文件系统写入只能走 `apply_sandbox_write` / `apply_guarded_write`。路径先规范化再判断：拒绝 `..` 逃逸、不同盘符、UNC / 其他卷、符号链接逃逸、写到另一个仓库，以及把前缀误判成子目录（`C:\wt` 不含 `C:\wt-other`）。未授权或越界时不创建目标文件，结果写入既有 Child / 父快照字段 `sandbox`（`TicketResult` / `TicketSnapshot`），阶段进入 `Failed`，不另开第二套 Query。异常不得被当成成功吞掉。

Windows 路径（盘符、混合分隔符、大小写、`\\?\\` 长路径前缀、超过 260 字符的路径）按 Windows 规则验收；在 Linux 上用策略测试覆盖这些形态。

## 预留写码 CLI 约定（对齐 DP-46，不实现运行时）

若构建写码命令，唯一允许的形态是在授权 worktree 内：`agent -p --force --trust --workspace <授权目录>`。禁止 CLI `--worktree`。密钥只从配置根目录文件 `CURSOR_API_KEY` 注入环境变量，禁止 `--api-key` 进命令行，不得进入 History、证据或日志。缺少配置根目录或 key 必须显式失败；非 0 退出不得吞掉。本票不调用现场 Cursor CLI，不自建 agent 循环或模型网关。

## 默认不自动 push / 合并（对齐 DP-31）

沙箱与写码命令构建器不得执行 `git push`、`git merge` / `rebase`，也不得改全局 Git 规则。开远程 PR 的授权条件未拍板前标 `待证`，默认视为未授权。[DP-31](https://weiperfect007.atlassian.net/browse/DP-31) 已把该默认写成写码验收，并要求指向生产的 push / 合并 / 发布被拒且留下记录。本票只在授权 worktree 内产生产物。

## 父 Workflow

父 / Child Workflow 模块仍保持确定性：不调用 LLM、不读 `CURSOR_API_KEY`、不启动 Cursor CLI、不做文件系统写入。可选的 `StoryInput.sandbox_write` / `TicketInput.sandbox_write` 只是在正式写码 Worker 落地前预留的显式沙箱写入请求，不是 [DP-21](https://weiperfect007.atlassian.net/browse/DP-21) 交付物清单。生产 CLI 不填写该字段。

## reopen 与既有门禁

不回退 [DP-16](https://weiperfect007.atlassian.net/browse/DP-16) / [DP-17](https://weiperfect007.atlassian.net/browse/DP-17) / [DP-18](https://weiperfect007.atlassian.net/browse/DP-18) / [DP-19](https://weiperfect007.atlassian.net/browse/DP-19) 门禁。Spike 默认 4 小时仍为待证。`reopen` 仍不继承方案 / Spike / 清单 / Jira key（待证），也不复用已乱掉的工作区。

## 验收与测试

单元与 WorkflowEnvironment 测试证明：授权内写入成功；越界 / 逃逸 / 其他盘符 / 长路径被拒并记录；未授权前不写外部仓库；父 Workflow 源码不含 LLM / Cursor CLI 调用；写码 argv 含 `--force --trust --workspace` 且不含 `--worktree` 或 `--api-key`；沙箱路径不自动 push / 合并。现场 History 打在已运行的官方 Temporal（`TEMPORAL_TARGET`，例如 `host.docker.internal:7233`），覆盖越界写入被拒并记入快照，使用临时授权树和假 Jira，不起临时 Temporal 服务，不写真实 Jira 票，不调用现场 Cursor CLI。
