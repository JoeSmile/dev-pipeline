## 检索范围与有效命中

方案阶段只检索 **规范** 与 **历史事故**。其他语料根目录标 **待证**，不能当成有效命中。实现模块为 `dev_pipeline.retrieval`（纯判定，无 I/O）与 Activity `retrieve_scheme_knowledge`（读授权语料）。父执行 `DevPipelineWorkflow` 只编排和记账，保持确定性。

有效命中必须同时满足：类别属于上述范围、非空 `id` / 标题 / 摘录、分数不低于配置中的最低分。最低分与语料根目录在签批前均为 **待证** 占位；测试使用配置根目录内的夹具语料，不调用现场检索服务。可选 `rag.toml` 样例见 `docs/examples/rag.toml`。语料路径必须落在配置根目录内，越界拒绝。

## 四条路径与执行记录

合法 `decide_scheme` 在写入取舍记录之后、进入 `SchemeDecided` 之前，走本边界。忽略客户端传入的 `真实命中`。查询快照在现有 `snapshot.scheme.retrieval` 上留下标记，并在 `snapshot.scheme_retrieval` 留下详细记录，不另开第二套 Query。

| 路径 | 标记 | 行为 |
|---|---|---|
| 检索成功 | `检索成功` | 记录有效命中，可写「已检索到」；用量记入预算账本 |
| 无命中 | `无命中` | 命中列表为空，不得写「已检索到」或「真实命中」；用量仍记账，并按 DP-12 对 `rag` 路径「无新证据即停」 |
| 检索失败 | `检索失败` | 配置 / 语料不可用或 Activity 失败时降级；命中列表为空，不得默填成功证据；已发生的尝试记入账本 |
| 超预算 | `超预算` | DP-12 闸门拒绝启动 Activity，不检索，不记账一次假搜索，不写成功证据；超限记 `Bad` |

未配置 `rag.toml`、语料根目录仍为待证时，Activity 仍会执行，但结果明确记为 **桩**，用量为 0，不得看起来像已经做过真实检索。`run_rag` 保留为预算闸门的通用桩，返回值标明「桩：未执行真实检索」；方案阶段改走 `retrieve_scheme_knowledge`，不再用该桩冒充命中。[DP-17](https://weiperfect007.atlassian.net/browse/DP-17) 的拍板字段与分支不变；只读继承的方案不再检索一次。

失败或空检索不得阻塞已合法的方案拍板：阶段仍按有无红线级假设进入 `TicketsReady` 或 `Spike`。
