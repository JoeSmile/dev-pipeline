# DP-30 决策记录

本记录固化 [DP-30](https://weiperfect007.atlassian.net/browse/DP-30) 对 `abort` / `reopen` 产物处理的主流做法。不扩展范围：不实现 Signal 接口本身（见 [DP-10](https://weiperfect007.atlassian.net/browse/DP-10)），不自动合并，不自动改 L0 / 全局 Skill，不产品化远程 PR 的开启或授权（见 [DP-31](https://weiperfect007.atlassian.net/browse/DP-31)）。

## abort

合法 `abort` 仍把父执行带入 `Blocked`，取消仍在运行的 Child，并在现有 Query `snapshot.abort_record` 留下可回放记录。清理 I/O 只在 Activity `recycle_aborted_execution` 中进行，Workflow 保持纯净。Temporal History 不予删除。

回收范围仅限本 `execution_id` 创建的未合并工作区与本地分支，包括授权根下的 `<authorized_root>/<ticket_id>/<execution_id>` 目录，以及该执行在授权根内创建的 git worktree / `ticket/<ticket_id>/<execution_id>` 本地分支。不回收同胞 execution 的工作区，不删除授权根本身，也不把 `D:\projects\dev-pipeline` 这类仓库外的主工程当成目标 Story worktree。若工作区指向授权根之外的 git 仓库，跳过回收并记录待人工处理。回收必须对 Windows 路径安全，且不得跟随符号链接删除授权树之外的目标。

已存在的远程 PR 不得自动关闭或合并。Activity 只检测并在 snapshot 上记录「待人工处理」。具体标记方式（标签、评论、指派等）仍为 `待证`，本票不发明已签字的生产标记方案。测试用桩 PR 证明 close / merge API 不被调用。默认路径仍然不开远程 PR。

## reopen

`reopen` 仍只在 `Blocked` 或 `Done` 接受，且必须使用新的 `execution_id` 启动独立新父执行。旧执行保持终态，不再被写入（不再向旧工作区、旧进度日志或旧分支追加产物）。新执行使用新的工作区路径；即使旧目录在未 abort 的 `Done` 路径上仍存在，也不得复用或写入该乱掉的工作区。

新执行只读继承：完整范围、方案、假设，以及已关闭 Ticket 的证据（Verified / 带验证证据的 Dropped）。Spike 假设若已在方案假设清单中，随假设继承；Spike 结论记录、审查裁决、`review_override`、`promote_rule` 与 Retro 晋升等未列入票面的字段保持 `待证`，不得静默扩权或当成新裁决重放。

## 非目标

不自动合并。不自动升级全局规则。不产品化 DP-31 远程 PR。不把 Jira 票标为 Done。
