# DP-14 决策记录

本记录固化 [DP-14](https://weiperfect007.atlassian.net/browse/DP-14) 把父 Workflow 阶段变更镜像回 Jira 票的主流做法。失败策略已在票中锁定，不是待证。自定义字段的具体名称/ID 仍为**待证**，必须可在配置根目录覆盖。不扩展范围：不把 Jira 字段或评论变更当成编排指令，不把 DevPipeline 阶段映射成 Jira 工作流状态，不另开第二套 Query。

## 真相来源

Temporal History 是唯一真相。Jira 只是给人看的镜像。同步失败不得改写或回写父执行阶段；也不得根据 Jira 上过期或被手改的值去改 Workflow。入站的评论 / 字段变更不产生 Signal，也不触发阶段转移。

## 默认镜像方式

不把 `Intake` / `ScopeLocked` / `TestDeploying` 等阶段映射到 Jira 的 To Do / In Progress / Done。改 Jira 状态会撞上项目工作流，看起来像在用 Jira 编排。

默认镜像是一条**幂等、带明确前缀**的 Jira 评论。该项目（team-managed）始终可以写评论，不依赖未批准的自定义字段。

- 前缀：`【DevPipeline 阶段镜像】`
- 正文含当前阶段、`execution_id`，并写明「Jira 只是镜像，不是编排器；阶段以 Temporal History 为准」
- 同一 `execution_id` 只维护一条阶段镜像评论：能找到则更新，找不到则新建。Activity 重试不得再贴一条重复评论
- 若 `jira.toml` 配置了 `stage_field`（字段名或 `customfield_*`），在写评论的同时覆盖该字段为当前阶段英文值。未配置则只写评论
- `stage_field` 的具体名称/ID 仍为**待证**，必须可在配置根目录的 `jira.toml` 覆盖。样例见 `docs/examples/jira.toml`

## 何时同步

在父执行每次阶段变更之后调度 Activity（含启动后的 `Intake`，以及之后所有经由 `_move` 的合法转移）。Issue key 复用 Intake / 启动载荷上已有的 `intake.jira_key`（[DP-13](https://weiperfect007.atlassian.net/browse/DP-13)）。没有 Jira key 时不同步，以免无票的测试或手工启动误打外部系统。`reopen` 启动新执行时必须带上同一份 `intake`，以便新执行继续镜像同一张票。

## Activity、重试与滞后

全部 Jira I/O 放在 Activity，Workflow 保持确定性。密钥只从配置根目录读取，不进命令行、不进会落入 History 的 Workflow 参数，也不进证据日志。Activity 入参只有 issue key、阶段、`execution_id`、`config_root`；返回只有 key、阶段和是否写了评论/字段。禁止把令牌、完整 Issue 或思考过程写入 History。

- 同步 Activity `mirror_parent_stage`：显式 `start_to_close_timeout`，允许重试（网络 / 5xx / 429）
- 配置缺失或非法（缺 `jira.toml`、缺令牌文件、字段不合法）以中文错误可见地失败，且不可重试，避免空转。不得挂起，也不得当成成功
- 重试耗尽或不可重试失败后：父执行阶段不变；在现有 `snapshot` 上记录 `jira_mirror`（`lagged=true`，`lag_marker=镜像滞后`，以及不含密钥的中文原因）。然后尽最大努力再调一次 `mark_jira_mirror_lag`，尝试在票上留下带前缀 `【DevPipeline 镜像滞后】` 的评论，使票面也能看出同步未完成。该标记失败不得让 Workflow 失败或改阶段
- 后续阶段若同步成功，清除滞后记录并更新 `last_mirrored_stage`

滞后状态挂在现有父执行 Query `snapshot` 的 `jira_mirror` 字段上，与 [DP-27](https://weiperfect007.atlassian.net/browse/DP-27) 对齐，不另开第二套 Query。

## 配置

配置文件是配置根目录下的 `jira.toml`。Worker 启动不强制要求该文件（Jira 是镜像，不是编排前置条件）；缺文件只让镜像 Activity 失败并进入滞后。样例不包含真实令牌。令牌放在配置根目录内的独立文件，由 `api_token_file` 指向（只允许配置根下的文件名，禁止路径穿越）。

## 验收与测试

阶段变更后，对应 Jira 票（测试用假客户端或内存票即可）必须能读到当前阶段。同步失败有重试和滞后标记，且不得用 Jira 覆盖 History。不把 dry-run 或仅有 History 记录当成 PASS；测试必须真正走到镜像路径。若没有安全的一次性夹具票和凭据，现场 Jira 测试干净跳过，仍用假客户端和 `WorkflowEnvironment` / History 断言覆盖该路径。不要用 DP-14 本身或其它真实项目票做会刷评论的现场探测。
